# HyperFusion v0.10.0 재감사 후속 수정

2026-10-08 첨부 재감사 보고서의 7개 잔여 지적을 프로젝트 코드와 대조해 수정했다. 버전은 유지한다. 기존 20개 지적 전체를 새로 재감사한 보고서는 아니며, 이번 변경과 회귀 검증의 결과를 기록한다.

| 지적 | 조치 | 검증 |
|---|---|---|
| 1. `begin`에서 BLOCKED 저장 후 예외가 나면 정산 누락 | `run`의 예외 경로에서도 저장된 상태를 다시 읽고 종료 전이를 정산한다. | 프로젝트 T1의 BLOCKED·지표 기록·T2 완료 후 체크포인트 도달 |
| 2. 반복 CLI 프로브의 일시적 실패가 최종 결정이 됨, PLAN/REDO에서 교체 불가 | 배치 판단은 실행 파일 해석만 수행하고, 도움말/버전 프로브는 `begin`의 lease 획득 전에 수행한다. 프로브 실패는 phase·예산을 유지한다. PLAN/REDO의 실행 파일이 없으면 대체 단계로 이동하고 다른 일꾼을 지정할 수 있다. | takeover 허용/금지 구성 모두 프로브 실패 후 동일 일꾼 재시도, PLAN/REDO 교체, 같은 호출에서 교체 |
| 3. 스냅샷이 무시된 `.gitignore`와 의존성 파일을 못 봄 | 자기 자신도 무시하는 `.gitignore`를 보호 파일 목록에 넣는다. 일반 의존성 파일의 내용 감시는 도입하지 않고 한국어·일본어 README에 한계를 명시한다. | VERIFY에서 숨긴 `conftest.py`와 `.gitignore`를 만들면 트리 변경으로 복구 요구 |
| 4. JSON 비밀값 누락 | 비밀값 키 뒤의 닫는 따옴표를 허용한다. | JSON `password`·`apiKey`, 작은따옴표 키 거절 및 장부 내용 제거 |
| 5. 테스트 대역이 프로브 중 루트에 `stray.txt` 생성 | tamper 공격은 실제 작업 실행에서만 수행한다. 저장소에 추적되던 부산물도 삭제한다. | 별도 호출 폴더에서 버전 프로브 후 파일 생성 없음 |
| 6. Windows 심볼릭 링크 테스트의 권한 오류 | Windows에서는 디렉터리 정션을 사용한다. | 정션 경유 프로토콜 쓰기 거절 |
| 7. Windows npm CLI의 확장자 없는 셸 래퍼를 먼저 선택 | PATHEXT 후보를 확장자 없는 후보보다 먼저 검사하고 `.cmd`의 실제 진입점을 해석한다. | 이름/PATH 및 절대 경로 모두 `.cmd`에서 Node 진입점으로 해석 |

3번은 **부분 해결**이다. 이미 무시된 `node_modules/dep/index.js` 같은 일반 의존성 파일의 내용 변경은 여전히 감시하지 않는다. 무시된 전체 파일을 포함하면 테스트 산출물까지 변경으로 잡히므로 이번 수정에서는 포함하지 않았다. 실행 파일이 실제로 없는 경우에는 기존 예산·takeover 정책을 적용하지만, 실행 파일이 있고 도움말 프로브만 실패한 경우에는 종료 상태로 확정하지 않는다.

검증 결과: Windows에서 `npm test` **202개 통과, 실패·건너뜀 0개**(약 146초). 기존 192개에 회귀 테스트 10개를 추가했다. `git diff --check`도 통과했고, 테스트 후 저장소 루트에 `stray.txt`가 다시 생성되지 않았다. 첫 샌드박스 실행은 임시 Git 저장소의 `.git/config` 쓰기 제한으로 중단됐으며, 승인된 실행 경로에서 전체 검증을 완료했다.

결과는 **6개 해결, 1개 부분 해결**이다. 테스트는 대역 CLI를 사용하며 실제 벤더 모델 호출이나 Grok의 Bash/Edit 규칙 해석 검증을 포함하지 않는다. 첨부 보고서의 외부 CLI 규칙 해석과 도구 체인 환경변수 관련 확인 사항은 그대로 남는다.
