# A급 순서 시험 (실험 계획)

상태: 계획. 판정 기준은 아직 확정하지 않았다. 돌리기 전에 사용자가 확정한다.

## 무엇을 정하려는가

A급 투입 순서를 Terra → Grok → Sonnet에서 **Terra → Sonnet → Grok**으로 바꿀지 정한다.

[일꾼 역량 시험](worker-capability-trial.md)(75회)에서 숨김 시험 전부 통과는 Terra 15, Sonnet 15, Grok 13이었다. "3회 이상 차이" 기준에 못 미쳐 순서를 그대로 뒀다. 하지만 Grok은 일꾼 시간이 훨씬 길었다(중앙값 25.5분, Sonnet 5.2분). 그 시험의 기준은 시간을 판정에 넣지 않았으므로, 시간을 넣는 기준을 새로 정하고 시간을 제대로 재는 회차를 따로 돌린다.

Terra의 자리(맨 앞)는 묻지 않는다. 통과 15/15이고 가장 빨랐다(중앙값 3.4분).

## 왜 새로 돌리나

앞 시험의 시간은 판정에 쓰기 어렵다. 75회 중 55회가 회사별 4줄 동시 실행이었다(`concurrent_lanes: 4`). 하나씩 돌린 시험은 대상마다 4회뿐이다.

| 대상 | 하나씩 돌린 4회의 일꾼 시간(분) |
|---|---|
| terra | 2.7 (L01), 5.6 (L02), 5.8 (L03), 1.4 (L04) |
| sonnet | 5.6 (L01), 오류 (L02), 5.3 (L03), 2.7 (L04) |
| grok | 25.5 (L01), 25.9 (L02), 오류 (L03), 17.4 (L04) |

차이는 크지만, 과제마다 1회씩이고 L05가 없다.

## 비교 대상과 과제

- 대상: terra, sonnet, grok. 설정은 앞 시험과 같다(Terra medium, Sonnet medium, Grok high, 구현 시간 제한 60분, Grok 루프 60).
- 과제: HF-L01~L05 다섯 개 모두.
- 횟수: 과제마다 대상마다 2회. 모두 30회다.
- **하나씩 돌린다(`--parallel` 없음).** 돌리는 동안 이 컴퓨터에서 다른 일꾼, 벤치마크, 전체 테스트를 돌리지 않는다.

예상 시간: 한 회차에 Grok 약 2시간, Terra 약 20분, Sonnet 약 25분이다. 두 회차와 채점을 합치면 약 6시간이다.

## 재는 것

- 시간: 일꾼 시간(`usage.wall_ms`)이다. 이번 30회의 기록만 쓴다.
- 품질: 숨김 시험 전부 통과(`all_hidden_passed`) 횟수다. 앞 시험의 15회와 이번 10회를 합친 25회로 센다.
- 오류: `errored` 횟수다. 품질과 같이 25회로 센다.
- 범위 밖 수정: 앞 시험과 같다.

## 판정 기준 (제안)

**돌리기 전에 아래 숫자를 확정하고, 결과를 본 뒤에는 바꾸지 않는다.**

넷을 모두 만족하면 순서를 Terra → Sonnet → Grok으로 바꾼다. 하나라도 못 미치면 지금 순서를 둔다.

1. **품질이 같거나 낫다.** Sonnet의 숨김 시험 전부 통과 횟수(25회 중)가 Grok 이상이다.
2. **충분히 빠르다.** Grok 일꾼 시간 중앙값이 Sonnet의 **2배 이상**이고, 차이가 **10분 이상**이다. 짧은 과제에서 배수만 크게 나오는 경우를 거르려고 두 조건을 같이 본다.
3. **과제 하나 때문이 아니다.** 과제별 중앙값으로 비교해 Grok이 Sonnet보다 느린 과제가 다섯 중 **넷 이상**이다.
4. **오류가 많지 않다.** Sonnet의 오류 횟수(25회 중)가 Grok보다 **2회 이상 많지 않다.** Sonnet은 앞 시험에서 L02에서 CLI 종료 코드 1로 두 번 끝났다(남은 코드는 둘 다 5/5 통과).

시간을 기준에 넣는 이유: 순서는 첫 시도에 누가 들어가는지를 정한다. 품질이 같다면 리드가 기다리는 시간이 짧은 쪽이 앞에 서는 것이 맞다. 리드 토큰은 이 시험에서 재지 않는다(일꾼만 돈다).

## 실행

```bash
git pull
node tools/worker-trial-batch.mjs run ../hf-trials-order --reps 2 --arms terra,sonnet,grok
```

- 새 폴더(`../hf-trials-order`)를 쓴다. 앞 시험 폴더와 섞지 않으며, 시험 이름이 같아도 저장소 경로가 달라 상태 폴더가 겹치지 않는다.
- 끊겨도 같은 명령으로 이어 돌린다.
- 진행 확인: `node tools/worker-trial-batch.mjs status ../hf-trials-order --reps 2 --arms terra,sonnet,grok`
